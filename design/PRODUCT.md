# PANTHEON · 万神殿 — 产品定义

> 你的灵魂不是一种人格。它是一座万神殿。

## 1. 这是什么

神话原型驱动的人格叙事与标签系统。用户完成一次情境测试后，得到的不是一位神，而是一套**神格谱系**：主神格、副神格、阴影神格、隐藏神格，以及它们之间的协作、张力与压制关系。

产品的目标不是回答 “Which god are you?”，而是回答：

> **你的内心，住着怎样的一座万神殿？**

其中最具区分度的输出是**内在神战**（两个高匹配、高张力、方向相反的原型）——用户记住的往往是这一句：

> 你很讨厌别人控制你，但你自己又很想建立一套完全由你掌握的系统。

## 2. 这不是什么

不是临床心理测试，不是精神疾病诊断，不是医疗工具，不是命运预测，不是宗教判断，不是科学人格诊断。

可以吸收原型心理学、人格心理学、神话学、文学与叙事学的设计思想；不得声称临床验证、医学准确性或科学诊断能力。

## 3. 优先级

1. 结果解释质量 > 神格数量 > 视觉炫技
2. 人格结构可信感 > 算法复杂度
3. 数据驱动、可维护 > 大量特殊 if-else
4. 复杂但可理解 > 数学上复杂但不可解释

## 4. 成功标准

用户完成后能说出具体的一串东西，而不是一个名字：

> “我是 Prometheus 主神格、Athena 副神格、Odin 阴影、Dionysus 隐藏，称号是‘盗火的筑世者’，而且它说我最矛盾的地方是……”

如果用户只能说 “哦，我是雅典娜”，这个项目就失败了。

## 5. 结果页结构

1. **Hero** — 称号 + 主神格 + 副 / 阴影 / 隐藏
2. **核心命题** — 一句话人格命题
3. **神格构成** — Top 5–7 归一化构成（横向条）
4. **人格图谱** — 16 维雷达（核心 8 维 / 完整 16 维）
5. **为什么是 X？** — 你 vs 主神格叠加雷达 + 最大差异说明
6. **主神格** — 长文
7. **副神格** — 重点是“你怎样实现主神格的欲望”
8. **阴影神格** — 受威胁时的自我保护方式
9. **隐藏神格** — 你没活出来的自己
10. **内在神战** — 视觉 + 核心矛盾
11. **神格觉醒** — Dormant → Awakened → Overawakened → Fallen
12. **力量与代价**
13. **Share Card**

报告是**模块化拼装**，不是固定长文：主神格基础分析 + 主×副关系 + 主×阴影关系 + 隐藏对照 + 主导维度分析 + 冲突分析。常见组合（Prometheus×Athena、Odin×Loki、孙悟空×Athena 等）走专门文案，其余走通用模板。

## 6. 用词规则

不用“优点 / 缺点”，用：**力量、代价、觉醒、阴影、堕化**。

结果必须允许不好听：

> 你很擅长建立结构，但可能低估结构对他人的压迫感。
> 你极度厌恶别人控制你，却未必同样敏感于自己控制别人。

但只描述**模式**，不给人定罪：

> 当事情开始偏离计划时，你可能会通过增加控制来重新获得安全感。

禁止 Barnum 文案（“你有时自信，有时也会怀疑自己”），禁止 AI 套话堆叠（“不仅仅是……更是……”），禁止整篇玄学。

## 7. 隐私与可信度

- 答案只在用户设备上处理，不上传。结果页明示这一承诺。
- 每个结果记录 `testVersion / scoringVersion / deityDatabaseVersion / resultVersion`，算法升级后旧结果知道自己来自哪个版本。
- 相同答案 + 相同版本 ⇒ 完全相同结果，包括称号。禁止随机。

## 8. 阶段路线

| 阶段 | 内容 |
| --- | --- |
| Phase 0 | 项目骨架、四份设计文档、TS schema、维度定义、校验框架 |
| Phase 1 | 30 个差异极大的神格、40–48 题、overall/primary/secondary + 三张图 |
| Phase 2 | 60+ 神格、Shadow、Hidden、关系库、内在神战 |
| Phase 3 | 称号生成器、觉醒轨迹、轨道图、Share Card |
| Phase 4 | 80–100 神格、simulation、碰撞分析、文案重写 |

每个阶段结束必须报告：完成内容、当前算法、神格数、题数、测试结果、simulation 结果、发现的问题、下一步建议。
